The vault upgrade adds state that every node must track identically: signer sets, vaults, Yellowback positions, attested prices. Each C++ node folds that state into one statehash per block. Kogany has to produce the same bytes.

The encoder is separate from the database

Kogany stores state in Zakura's own database layout, which differs from ycashd's. So the canonical preimage encoder is written apart from storage, following the published serialization rules rather than either node's on-disk format. Storage can change; the hash can't.

Where Rust differs

  • Map order. A HashMap iterates in random order, while the C++ nodes iterate ordered maps. Kogany uses BTreeMap wherever order reaches the hash.
  • Overflow. Release builds wrap on integer overflow. Consensus arithmetic uses checked_* and 128-bit intermediates only, and the math test cases run in release builds as well as debug.
  • Concurrency. Zakura verifies the transactions in a block concurrently. Vault acts must be applied in order, so they run in contextual validation against a snapshot of the parent block's state.
  • Checkpoints. Zakura commits checkpointed blocks without contextual checks. Kogany computes vault deltas on every commit path, and its checkpoints stop before the vault epoch.

The test

On one devnet, all three nodes mine and relay together. Every 100 blocks a harness compares their state hashes, and any disagreement fails the run. The same golden vectors, generated once from the C++ lines, are replayed in Kogany's unit tests.
