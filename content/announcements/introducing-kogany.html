Today we're starting Kogany, a Ycash full node written in Rust. It's our fork of Zakura, the consensus-compatible Zcash node from the Zebra lineage, taken at commit 2b062412c5 on Zakura's main branch, just after its 1.7.0 release.

Nothing here is a release yet. Kogany becomes a release line only after the full three-node test at the end of wave W9, by explicit sign-off of the Yellowback lead architect.

Why a third node

The vault upgrade already runs on two C++ node lines, ycashd 4.5 and 6.20. Both come from the same family of code, though, so a mistake in shared logic can hide in both. Kogany is an independent implementation in a different language and architecture. Running all three side by side and requiring the same vault and Yellowback state hash at every block is the strongest consensus test we can build.

The plan

  • W0–W1: scaffolding, then Ycash on Zakura: branch IDs, Equihash (192,7), the Development Fund, checkpoints, P2P, a full sync beside ycashd.
  • W2–W4: the Vault epoch, script and post-quantum verification, and the vault primitive with its set state and reorg handling.
  • W5–W8: the YED rule module, relay policy, the read RPCs (rpcversion 8) and mining.
  • W9: the whole Yellowback suite against all three nodes on one devnet, with the wallet served by yewd.
