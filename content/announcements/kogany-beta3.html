koganyd @KOGANY_TAG@ is out: Kogany, the Ycash node on Zakura, with the vault network upgrade and the Ycash Yellowback (YED) rule module. Binaries for Linux (x86_64, aarch64) and macOS (Apple silicon) are on the release page; the download page shows how to verify them.

It is a pre-release, for testing. Kogany is not yet a qualified Ycash node line. Run it on the Ycash testnets and expect resyncs and breaking changes between pre-releases. No activation height for the vault upgrade is set on mainnet.

What you must do when upgrading

  • Allow a minute or two for the first start. It upgrades the database once, from state format 30.2.0 to 30.3.0. The node serves no RPC until it is done, and an interrupted start continues where it stopped. The step is one-way, but a beta2 koganyd still opens the upgraded database.
  • On the fast testnet, upgrade before the development fund's mandate ends there. The height is set when the release candidate is cut, and the release notes name it. From that height a block without the fund output is valid, and an older node rejects it and leaves the chain. Mainnet and the slow and legacy testnets are unchanged.
  • Clients: rpcversion is 10 (it was 9). A client that requires exactly 9 must accept 10.
  • Miners: the development-fund donation now defaults to 0 %. To keep donating after the mandate, set ydf = 5 under [mining].
  • Explorer nodes: set [rpc] insight_explorer = true for ycashd's -insightexplorer input fields and blockfee. It is off by default; keep it off where untrusted clients reach the RPC port.

What changed since beta2

  • Value pools by address type. getblockchaininfo and getblock answer transparentPools beside valuePools, and getblockchaininfo answers the chain's transactions count. Where the node does not know a figure it says so (monitored: false) instead of guessing.
  • A coinbase for each miner's own address. getcoinbasetemplatefor builds the coinbase for a transparent, Sapling or post-quantum miner address, so a pool can pay each miner the block reward and every fee at its own address. A Sapling coinbase needs sapling-output.params, read at start from ~/.zcash-params or mining.sapling_output_params.
  • Deep reorganisations. Like ycashd, koganyd refuses a reorganisation deeper than 99 blocks: it stops, and stays stopped across restarts until an operator removes the record it writes.
  • JSON-RPC 1.0 batches, as block explorers send them, get one answer per request, as on ycashd.
  • Builders: the Rust toolchain is pinned at 1.100.0.

The wallet

koganyd has no wallet of its own. yewd is the wallet in front of it, built from source. The release notes list where it still differs from ycashd's wallet.
