Network upgrade · branch ID 0x6d5b7a31

The vault upgrade

A height-activated Ycash network upgrade that adds vaults. A vault is YEC locked under rules that every full node checks. Yellowback (YED) is the first rule module built on it.

No activation height is set on any public network. The mainnet height and founding attestor set are fixed by the release that passes the upgrade's gates. Until then the upgrade runs on regtest and devnet only, activated with -nuparams=6d5b7a31:<height>.

What it changes

  • Vaults. YEC locked by a script template, released only with the approval of a bonded signer set. If the set goes dormant, the owner can always recover the coins.
  • Post-quantum signatures. Vault owners sign with SLH-DSA and YED holders with Falcon-512, from the first block of the upgrade.
  • New opcodes, allocated above OP_NOP10 and active only under the Vault branch ID: OP_CHECKSEQUENCEVERIFY (0xb2), OP_CHECKSETSIG (0xc0), OP_CHECKSETDORMANT (0xc1) and OP_CHECKPQSIG (0xc2).
  • Transaction version. Vault-era transactions stay at version 4 (Sapling). Orchard and version 5 are not part of the upgrade.
  • Yellowback. One registered rule module, YED\0: mint YED against YEC locked in a vault, redeem it, and let anyone claim undercollateralized positions. The module uses attested prices, and its fee rules are enforced by consensus.
  • RPC. The node reports rpcversion 8 and adds the read RPCs vault_*, set_* and yed_*.
