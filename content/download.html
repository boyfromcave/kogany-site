Building from source

Developers can build the integration branch now. The ycash cargo feature selects the Ycash network; without it the binary behaves like upstream Zakura on Zcash networks.

git clone https://github.com/boyfromcave/kogany
cd kogany && git checkout upgrade/vault
cargo build --release --locked --features ycash

Until wave W1 lands, a ycash build won't sync the Ycash chain. For a node that runs today, use ycashd 6.22.x.

Release binaries

Each release will publish prebuilt binaries and a source tarball on GitHub. A release workflow builds from a tag and refuses a tag whose version doesn't match its line or whose upgrade heights are unset. The channels listed on this page will be the only official ones. A Kogany binary offered anywhere else is not from this project.

Verifying releases

Verification has three parts: the maintainer signature over SHA256SUMS.txt, your downloads against that file, and the GitHub build attestation proving CI built each asset from the repository. Once a release exists, the full commands will be:

gh release download -R boyfromcave/kogany
minisign -Vm SHA256SUMS.txt -P <key published above>
sha256sum -c --ignore-missing SHA256SUMS.txt   # macOS: shasum -a 256 -c --ignore-missing SHA256SUMS.txt
gh attestation verify <binary> --repo boyfromcave/kogany

Expect a valid signature, OK for each binary, and a passing attestation. If any check fails, delete the download and report it.
