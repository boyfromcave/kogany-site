Wallet compatibility

yewd

ycashd has a wallet inside the node. Kogany, like Zakura, doesn't. yewd fills the gap: it serves the same wallet RPCs from a separate process.

What it is

yewd is the YEW wallet core run as a daemon. It's the third front end on that core, beside the mobile app and the web wallet, and lives in the same repository. It follows Kogany through the node's RPC and indexer streams and lightwalletd, and presents the ycashd wallet interface, Yellowback calls included, on its own port.

Why a separate process

It keeps the consensus node small, and it means the wallet logic is code that already runs in YEW's apps. It does add one hazard: a separate wallet can fall behind the node. So before answering any wallet call, yewd checks that it has caught up with the node's best block and mempool. If it hasn't, it returns an error rather than stale balances, and it rewinds cleanly through reorganizations.

Status

Planned. It is built alongside waves W5–W8 and is finished when the existing wallet contract tests and wallet scripts pass against Kogany plus yewd with no ycashd present.
