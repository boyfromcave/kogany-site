Fast bootstrap

Snapshots

A state bundle is a packed, checksummed copy of a node's data at an agreed block. With one, a new node starts in minutes instead of syncing from genesis.

No bundles are published yet. The snapshotter is built and tested against a stand-in node, but it has not yet run against a live testnet. When bundles exist, they're listed here from their manifest.

What a bundle is

Bundles use the ycash-state/1 format: a node's working files at a fixed height, with the fingerprints needed to check them. Before a bundle is published, two different node programs must agree on its fingerprints. A bundle only one implementation vouches for is never published.

Bundles are made for the public testnets first. A mainnet bundle would only follow a mainnet activation.

Trust

A node restored from a bundle trusts whoever produced it for the history before that height. Syncing from the network keeps a node fully self-validating. Use a bundle to save time on a testnet, and sync from genesis when that independence matters.

Kogany and imported state

Zakura can import some chain state from artifacts shipped with a release. For Ycash, Kogany turns that off. Vault and Yellowback state are never imported: Kogany computes them itself for every block it commits, including blocks reached through checkpoints. Checkpoints stop before the vault epoch, so every vault-era block is fully validated. This may be revisited once Kogany's vault state matches the C++ nodes'.

For the same reason, restoring a ycashd bundle into Kogany won't work: the two use different database formats.

Restoring into ycashd

The restore tool, ycash-bootstrap, ships with the node repositories. Its exact commands, with each bundle's height and checksum, will appear here alongside the first published bundle.
