Snapshots

Ycash mainnet state snapshots for bootstrapping a node from a recent block height instead of syncing from genesis. A snapshot is made by one node program and restores into that program only: pick the set for the node you run.

  • For Kogany koganyd Kogany state database, pruned or archive
  • For ycashd 6.22.x ycashd ycashd datadir, with or without the explorer indexes

Before you restore

Each card's restore steps fetch the latest manifest, then that height's files. Check the SHA256SUMS signature against the Ycash release key, check every file against SHA256SUMS, and unpack the state. A pruned Kogany snapshot needs the node set to pruned mode first.

Needs jq and minisign. aria2 downloads in parallel and checks the checksum as it goes; use the curl tab if it isn't installed.

Release signing key

Ycash release key {{ key_id }}

Every snapshot's SHA256SUMS, for Kogany and for ycashd alike, is signed with the Ycash release key, in SHA256SUMS.minisig beside it. Check the signature before you check the files: the signature proves the holder of the release key published the checksum list, and the checksum list then vouches for every file. The public key is:

ycash-release.pub · key id {{ key_id }}
{{ key_public }}

Also as a file: ycash-release.pub, for minisign -Vm SHA256SUMS -p ycash-release.pub. The first line of the key and of every .minisig names the key id; they must match. A signature from any other key is not a release signature.

What a snapshot asks you to trust

A node restored from a snapshot trusts the publisher for the state at that height. Syncing from the network keeps a node fully self-validating. Every snapshot is taken from a stopped node at an exact height and packed reproducibly. Each Kogany manifest records whether the ycashd snapshot at the same height names the same block. A ycashd node can recheck everything with -reindex-chainstate, which rebuilds its state from the snapshot's own blocks without downloading them again.

A Kogany snapshot is valid only for its state format (30.2.0). A Kogany build with a different format version ignores it and syncs from genesis. A pruned snapshot restores only into a node configured for pruned mode with tx_retention of at least 10,000 blocks, and the switch is one-way. An archive snapshot restores into either mode.
