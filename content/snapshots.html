Run a node

Start a new node, or replace an existing node's state with a recent snapshot. The commands use aria2 for parallel, checksum-verified downloads and need zstd. Use the curl fallback if aria2 isn't installed.

# 1 · stop the node first, if it is already running

# 2 · run in pruned storage mode
mkdir -p ~/.config
cat > ~/.config/kogany.toml <<'EOF'
[state]
storage_mode = "pruned"
EOF

# 3 · download the latest snapshot — resumable, checksum-verified
aria2c -x16 -s16 --checksum=sha-256=<sha256> \
  -o <snapshot>.tar.zst \
  <url from the manifest>curl -f -L -C - -o <snapshot>.tar.zst <url from the manifest>
echo "<sha256>  <snapshot>.tar.zst" | shasum -a 256 -c

# 4 · replace the state cache
mkdir -p ~/.cache/kogany
rm -rf ~/.cache/kogany/state
zstd -dc <snapshot>.tar.zst | tar -x -C ~/.cache/kogany

# 5 · start — the node resumes from the snapshot height, not genesis
kogany start

Command shape for illustration: the binary name, paths and state layout are published with the first Kogany testnet build, and this block then fills in each snapshot's exact file name, URL and checksum.

Trust, and what is never imported

A node restored from a snapshot trusts the publisher for the history before that height. Syncing from the network keeps it fully self-validating. Kogany never imports vault or Yellowback state from an artifact: before a snapshot is published, two different node programs must agree on its fingerprints.
